Electronic Medical Record

A real-world revamp of an Electronic Medical Record application used by healthcare professionals — refreshing the interface, adding features field users actually need, and turning a confusing, inconsistent UI into a clear, responsive experience.

Role UI/UX Designer
Focus UX Research & UI Design
Tools Figma

The Problem.

The existing EMR worked, but it fought its users: buttons and menus looked different on every screen — inconsistent styles, sizes, and patterns — so users could never be sure what to expect. Menus had no clear hierarchy, leaving users unsure what the next step was, and most flows were long-winded instead of straight to the point.

The goal of the revamp: keep what works, fix the inconsistency, and make every flow feel obvious — while adding the few features field users had been asking for.

Research: auditing before redesigning.

Because this is a real application in daily use, I started with a UI audit of the existing screens — cataloging every inconsistent button, menu, and layout pattern. Alongside it, I collected input from field users about which tasks take the longest and which features they need but don't have yet.

The audit confirmed the pattern behind the confusion: no shared component styles, no visual hierarchy inside menus, and flows that added steps instead of progress. These findings turned a vague "make it look better" request into a concrete list of design problems to solve.

Creating consistency in the healthcare interface.

The inconsistent buttons and menus were the root cause of user confusion, so the first fix was a unified design system. Colors, typography, spacing, and components were defined once — so every screen would finally behave the same way, and users could trust what a button would do no matter where they found it.

Design system - colors, typography, spacing and visual elements.

Reusable components for a scalable interface.

With the system in place, every button and menu was rebuilt from reusable components with defined variants and states. The inconsistency that confused users is now impossible to reintroduce — and future updates take a fraction of the effort.

Component library - reusable UI elements for the EMR interface.

Designing a better workflow.

With the foundations fixed, I gave every menu a clear hierarchy — so users always know where they are and what the next step is. Long-winded flows were cut down to the shortest path that still keeps medical data accurate.

The Outcome.

The revamped prototype was reviewed by the field users who work with the EMR every day. The feedback was positive: the interface finally feels consistent — one button always behaves like every other button — and the clearer hierarchy means less guessing about what to do next.

This project proved the value of starting with an audit: a concrete list of inconsistencies gave the redesign direction and made every decision defensible. Next, I would track task completion and time-per-task after release to measure the improvement with numbers, not just impressions.
